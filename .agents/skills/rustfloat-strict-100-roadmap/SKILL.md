# RustAndFloat 厳格100点判定とロードマップ

採点表は `harness-eval-coverage` の5カテゴリ×20点（各4点×5）を使う。**判定の厳しさはこのスキルが上書きする。** HANDOFF の「100点到達」は主張であり、得点ではない。

## 証拠グレード（1項目4点）

| グレード | 点 | 条件 |
|----------|----|------|
| 実機確認 | 4 | この会話か直近 Play で、ユーザーまたはコンソール／操作ログが成功を示している |
| コードのみ | 2 | 該当スクリプトに実装がある。Play 未確認 |
| 不明 | 0 | ファイルもログも無い。推測で埋めない |
| 破綻 | 0 | ユーザー報告・例外・手順どおりに失敗した。100点を禁止する |

コードを読んだだけでは 4 を付けない。実装の存在は「コードのみ」の上限。

## 手順

1. `harness-eval-coverage` の25項目をそのまま行にする。
2. 各行を Grep または HANDOFF で裏取りし、グレードを付ける。検索していない行は「不明」。
3. ユーザーが直近で壊れていると言った流れは、コードがあっても **破綻** にする。少なくとも次は毎回確認する。
   - レバー後、ダイブ確定前に浮く
   - 光の柱が割れ目手前で止まり落下する
   - タイトル待機が意図した場面になっていない
   - 解放空の楕円雲・光の筋が残る
4. 合計は 0〜100 の整数。95以上でも破綻が1つあればランクは「未出荷」。
5. ロードマップは **減点項目だけ**。満点の機能を再掲しない。

## 出力（見出し固定）

```markdown
## 判定
- 得点: NN / 100
- ランク: 未出荷 / 銀 / 金 / 満点不可（破綻あり）
- 100点を止めるもの: （0件なら「なし」）

## 減点一覧
| 項目 | 点 | グレード | 根拠（ファイルか未確認） |
|------|----|----------|--------------------------|

## 100点までのロードマップ
週次ではなく、Play で確認できる順。1段につき回復見込み点を書く。

1. 段名 — 回復 +N — 触るファイル — 完了条件（操作1つ）
2. ...

## 今やらないこと
満点に効かないpolishを1〜3個。
```

ランク帯: 破綻が1つでもあれば「未出荷」。破綻ゼロで 85〜94 は銀、95〜99 は金、100 は全行が実機確認のときだけ。

## 禁止

- 「実装済みだから4点」
- 減点しないロードマップ（機能追加の願望リスト）
- 1段に複数の無関係な修正を詰める
- `AdventureWorld.unity` と `Land_Terrain.asset` を改善案に含める

最後の確認は1問。次に着手する段を聞く。
